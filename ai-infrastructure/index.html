Exploring LLM performance, GPU workloads, and infrastructure monitoring through load testing and system configuration during my internship.

01 The Context

Behind every AI service, there is infrastructure.

During my internship, I was involved in activities related to AI infrastructure and system observability. One of the areas I explored was how an LLM service behaves under different workloads.

The work involved preparing test scenarios, running load tests, observing GPU performance, and analyzing metrics that could support capacity planning.

02 The Challenge

How does the system behave under load?

Testing an LLM service is not only about whether the model can return an answer. The system also needs to be observed through performance metrics such as throughput, Time to First Token (TTFT), and inter-token latency.

The challenge was to create structured test scenarios and analyze the resulting performance data while dealing with changing GPU conditions and incomplete monitoring data.

04 The Experiment

Putting the LLM under pressure.

I helped prepare activity lists and participated in LLM load testing using Virtual LLM Client with different GPU replica configurations.

One of the test scenarios used 50 input tokens and 300 output tokens. The resulting data was analyzed to understand request throughput, token throughput, TTFT, and latency.

Request Throughput Requests handled by the system
Token Throughput Token processing performance
TTFT Time to First Token Initial response latency
Latency Inter-token Time between generated tokens
05 Observability

You cannot optimize what you cannot see.

Monitoring was used to observe GPU and infrastructure conditions during testing. Prometheus was configured to collect metrics, while Grafana was used to visualize the system state.

06 Infrastructure Work

The LLM was only one part of the story.

My internship also exposed me to infrastructure and observability work beyond LLM testing. I worked with a MinIO cluster and explored its monitoring through Prometheus and Grafana.

I also worked on an NGINX setup as a reverse proxy and load balancer for multiple MinIO nodes, including troubleshooting Docker networking, upstream configuration, and internal DNS resolution.

07 Exploring LiteLLM

From exploration to deployment.

Later in the internship, I explored LiteLLM through installation, basic configuration, and functional testing. The framework was then tested through request simulation and internal client testing.

I also worked on deploying LiteLLM in an internal server environment and prepared configurations for a two-replica load testing scenario.

09 What I Learned

Performance is not just a number.

This experience helped me understand that working with AI systems also means understanding the infrastructure underneath them.

Load testing, monitoring, networking, deployment, and troubleshooting are connected. A performance result only makes sense when the environment and the conditions behind that result are understood.
